## 0. Фрагментация в IPv4

| Тип фрагмента | Условие | Фильтр | Пояснение |
|---|---|---|---|
| Первый фрагмент | Offset = 0, MF = 1 | ip[6:2] & 0x1FFF = 0 and ip[6:2] & 0x2000 != 0 | Смещение нулевое<br/>Флаг "Еще фрагменты" установлен |
| Средний фрагмент | Offset > 0, MF = 1 | ip[6:2] & 0x1FFF != 0 and ip[6:2] & 0x2000 != 0 | Смещение не нулевое<br/>Флаг "Еще фрагменты" установлен |
| Последний фрагмент | Offset > 0, MF = 0 | ip[6:2] & 0x1FFF != 0 and ip[6:2] & 0x2000 = 0 | Смещение не нулевое<br/>Флаг "Еще фрагменты" сброшен |
| Нефрагментированный пакет | Offset = 0, MF = 0 | ip[6:2] & 0x1FFF = 0 and ip[6:2] & 0x2000 = 0 или ip[6:2] & 0x3FFF = 0 | Смещение нулевое<br/>Флаг "Еще фрагменты" сброшен. Маска 0x3FFF проверяет оба условия |

## 3. Любой ICMP-пакет (пинг)

```
tcpdump -r capture.pcap -nn icmp
```

Найдена пара пакетов ICMP Echo Request / Echo Reply (обычный ping) до 8.8.8.8:

```
23:09:11.847641 IP 10.10.206.236 > 8.8.8.8: ICMP echo request, id 10449, seq 1, length 64
23:09:11.890087 IP 8.8.8.8 > 10.10.206.236: ICMP echo reply, id 10449, seq 1, length 64
```

## 4. Самый большой по размеру пакет в дампе
```
tcpdump -r capture.pcap -nn | grep -oE 'length [0-9]+' | awk '{print $2}' | sort -rn | head -1
```

Результат: самый большой пакет в дампе имеет длину **8192 байт**.
